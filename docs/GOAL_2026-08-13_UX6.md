# #1(P0) 完成手动重跑特性(接续上轮,收尾)

**用户诉求(已讨论定案)**: 选错模型(如只错 TTS)报错后,能**重新选模型** + **单独控制重跑哪些阶段**,
全手动可选;再回到自动。语义 = 「重跑」应能手动指定,不该只能整本自动重跑。

**已定案设计**:
- 失败/部分完成的任务行加「重跑…」按钮 → 对话框:
  - 模型重选: 3 个下拉(翻译引擎 LLM / 语音 TTS / 分词 NLP),默认「保持当前(书级绑定/推荐)」,
    选项 = 已登记模型(`AiduModelService.list()`)。
  - 重跑范围(单选): 自动(只跑失败/未完成) / 从翻译 / 从讲解 / 从语音 / 全部。
    (从翻译=清翻译+讲解;从语音=清语音+对齐;全部=清翻译+讲解+语音+对齐)
  - 「开始重跑」→ `AiduJobService.retryCustom(id, llmId, ttsId, nlpId, forceStages)`。
- 后端 `job_retry_custom`: 显式模型 id 覆盖(`model_repo.get(id).path`)否则沿用 `resolve_for_book`;
  `force_stages` 写进 job_request.json; 重入队。
- Python `Runner._apply_force_stages`: 启动时按 `force_stages` 调 `clear_stages` 清对应 checkpoint 字段
  (含下游级联),使 `is_done_sentence` 判未完成 → 只重跑这些阶段。

**收尾要做**:

# #2(P0) 词典守护启动超时「侧车未就绪」

**用户实测**: 点生词 → 「词义查询失败 (词典守护启动超时 (侧车未就绪))」。本地查词失败。

**现状**(`src-tauri/src/infrastructure/dict_daemon.rs`): 常驻词典守护 = spawn 侧车 `--lookup-server` 模式,
先写 `{"ok":true,"ready":true}` 行;Rust 用 `recv_timeout(LOOKUP_TIMEOUT=30s)` 等 ready 行,
超时 → Err("词典守护启动超时 (侧车未就绪)")。守护懒加载 2.4GB LLM(dict_server.py)。

**要排查的根因**(先实测定位,不猜):
- 侧车 `--lookup-server` 冷启动(加载 LLM)是否 >30s → 超时;
- prep 侧车路径解析不对(找不到/不是文件);
- ready 行未被消费/被其它输出顶掉(历史上踩过"ready 行顶掉首查响应");
- `dict_daemon::stop()` 与任务启动互斥后,守护没有重建/重建竞态。

**修**(实测后定): 至少要"超时可重试 + 明确人话";若冷启动慢 → 提高超时/异步预热/给进度反馈。
保持: 本地(词典 DB → 本地 LLM 守护)为主,绝不静默失败。

**验收**: 本地查词冷启动不报"侧车未就绪";失败时 UI 有可重试动作,不是死路。

# #3(P1) 生词查词本地优先,在线仅点击(不外发)

**用户诉求**: 「应该先使用本地。可以选择点击在线查询。本地能做完的事。不要留到在线。」

**现状**: `reader.rs::word_lookup` 已本地优先(词典 DB → 本地 LLM 守护),失败才在面板给
「用在线 AI 查一次」(且仅当在线引擎①开启,`dictionary_panel.js::_appendOnlineLookup`)。设计上已对,
但 #2 的守护超时让本地这条腿断了 → 用户以为"只能在线"。

**要确认/修**:
- 修 #2 后,本地查词应自愈;确认在线入口**只**在本地失败后、且需用户点一下才外发(现状已如此,回归确认)。
- 查词失败面板的「重试本地」与「用在线 AI 查一次」并置清晰,不诱导在线。

**验收**: 本地词典命中不碰守护/在线;守护命中不回退在线;只有用户显式点「用在线 AI 查一次」才外发。

# #4(P1) 生词面板不挡阅读 + 点阅读自动收起 + 底部是否查询历史

**用户诉求**:
1. 「生词界面要挡到阅读界面」——词典面板(`reader/components/dictionary_panel.js`,右侧 340px 滑出)
   盖住正文;应**点正文任意处自动收起**。
2. 「点阅读界面,让它自动收起」。
3. 「这么长的生词展示界面。下面这部分是不是有个查询历史记录?」——面板内容长(词/词性/音标/释义/
   例句/用法/搭配/来源/加词),**没有查询历史**;用户在质疑这长面板底部是什么、是否需要历史。

**修**:
- 点正文(面板外)自动收起: 加 document 级 click 监听(点 `dict-panel` 之外 → hide),或阅读器 `_onWordClick`/
  正文点击处 hide。注意与面板内部按钮(加词/发音/在线)不冲突。
- 长面板治理: 梳理各段必要性,过长内容可折叠(释义/例句/搭配分段可收)。**是否加"查询历史"**:
  先与产品判断——用户原话是疑问句,不一定要做历史;至少要回答清楚"底部那部分是什么"(是释义/例句/
  用法/搭配,不是历史)。若做历史:记录本次阅读会话查过的词(内存即可,不落库),面板底部小列表可点回看。

**验收(教训 8)**: 打开词典面板后点正文 → 面板收起(有 `.dict-panel` 消失/`open` 类移除的 DOM 断言);
面板各段结构清晰,无"疑似历史但不知所云"的长尾巴。
