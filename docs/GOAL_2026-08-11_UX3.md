# L1(P0)991 MB 成品丢失:善后 + 根因 + 备份补全

**已确认的事实**(勿重复调查):
- 迁移日志:`19:49:15 迁移完成: jobs_out 1 项` → `19:49:20 已清理旧位置`(源被删)。
- 现在 `%APPDATA%\aidulc\jobs_out\jobs` = **0 个文件**;原 edition 目录
  `job-1786205609337-11852-1` 不在磁盘、不在回收站、F: 全盘搜不到。
- `copy_tree_with_verify` 与 `count_and_size` 代码本身是**正确的**(复制后递归比对
  文件数+字节数,不等即报错保源)。既然校验通过,说明**复制那一刻源已经是空的**。
- 数据库完好(1424 词全在),**两本源 EPUB 都还在** `C:\Users\yoyos\Downloads\`。
- 审计者(我)在测得 991 MB 之后、迁移之前跑过 `cargo build --release` 与 `check.ps1` ×2。
  **无法排除是这段窗口里被删的**,但也没有证据指认。

**L1-a 根因定位(先做,不许跳过)**:排查"谁会删 `jobs_out` 下的内容"。重点看
`application/library_asset_service.rs::cleanup_orphan_job_dirs`(启动期调用,
`main.rs` 内)—— 它按"DB 里没引用的 job 目录"删文件。UX2 的 I3 给**批次**加了级联清理,
**要确认它有没有连带把 job 目录判成孤儿**。构造用例:DB 里 edition 的 `pack_dir` 指向
某目录 → 跑清理 → 断言该目录**不被删**。若复现,这就是根因。
**报告必须明确写结论:复现了(是它)/ 没复现(仍未知)。不许含糊。**

**L1-b 备份必须覆盖会丢的东西**:UX2 的"执行前自动备份"用的是
`transfer_service::export_aidu_data`,**只导数据库行**(实测 1.7 MB),
成品文件一个字节都没备。改为:迁移前对 `jobs_out` 做**校验和清单**
(每个文件的相对路径 + 大小 + 可选 hash)落盘,迁移后逐条比对;
清单不匹配 → **不删源、报错**。全量复制 991 MB 做第二份不现实,清单比对是可行折中。

**L1-c 删源前的最后一道闸**:`cleanup_pending` 删旧目录前,再核一次
"新位置文件数 ≥ 清单条数"。**任何一步不确定,宁可留着旧目录让用户手删。**

**L1-d 善后**:给用户一条明确路径 —— 书还在 `books` 表里但 `pack_dir` 已失效,
提供"重新生成译本"(复用现有创建译本流程,源 EPUB 路径已在 `books.source_path`)。

**验收**:L1-a 有明确结论;构造"迁移后目标缺文件"的用例 → 源**不被删**且报错(单测);
真实副本上跑一次迁移,报告给出前后文件数与字节数。

# L3(P0)「开始复习」点了没反应

**根因(实测)**:`reader/views/vocab_view.js:112`
```js
global.AiduStore.set({ reviewFocus: true });
window.location.hash = '#/vocab';   // ← 当前 hash 已经就是 #/vocab
```
给 `location.hash` 赋**相同值不触发 `hashchange`**,路由不会重渲染,所以什么都不发生。

**修**:不要靠改 hash 触发,直接调路由重渲染(`router.navigate('vocab')` 或视图自身
`this.render(this.host)`)。**顺带检查全项目还有没有同样"赋同值 hash 期待重渲染"的地方**
(教训 1:同类要扫,给清单)。

**验收**:实测点击路径 —— 点「开始复习」→ 进入专注模式;`Esc` → 退出且进度保留。

# L5(P1)排版:三处抱怨是同一个根因

用户在三个地方抱怨"间隔太远":生词本的 备份/恢复/导出(图2)、同步的 立即同步/拉取合并/更多
(图6)、模型与依赖的 扫描已有模型/添加自定义模型(图7)。

**根因**:`app.css:225` 的 `.page-header { justify-content: space-between }` ——
标题 + 2~3 个按钮被撑到整行两端,中间是巨大空白。**不是三个 bug,是一个布局模式用错了。**

**修**:标题靠左、动作按钮**成组靠右且组内间距固定**(`gap: var(--md-sys-space-2)`),
不要让按钮之间被 `space-between` 撑开。做成**一个共用的工具条组件/类**
(如 `.page-toolbar`),三处都用它,以后新页面直接复用。

**门禁**:`_smoke_views.mjs` 断言页头动作按钮容器使用共用类,且不出现
"按钮之间被 space-between 撑开"的结构(可查:动作容器必须是单一 flex 容器且带 gap)。

**验收**:三处截图对照;新增页面复用同一组件。
