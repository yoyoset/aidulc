# #1(P1) 译本展开状态持久化 + 轮巡增量更新

**现状问题**(UX4 M1-b 修好 toggle 后): 原版书库每 5 秒轮询 `job_list`(`library_view.js:166`)→
整列 `_renderBooks` → 所有 `.edition-body` 重建为 `collapsed`, **展开状态被冲掉**。轮巡本身
只读 DB 查进度, 不影响备料流水线(回答用户问题: 不影响进度), 但整列重建是浪费 + 造成折叠/闪烁。

**修**:
1. `this._expanded = new Set<bookId>`(constructor 初始化); toggle 时加入/移出; 重建卡片时
   按 set 决定 `.edition-body` 是否保留 `collapsed`, toggle 箭头同理(`▸`/`▾`)。
2. `loadJobs` 不再整列重建: 卡片加 `data-book-id`, 轮巡只更新对应卡片进度条
   (`.prep-bar-fill` 宽度 + `.book-progress-text`), 书卡本体不重建。

**验收(教训 8, 断言最终 DOM)**:
- 点 `.edition-toggle` 展开后, 触发一次轮巡(模拟 job poll / store change), 断言该书卡
  `.edition-body` **仍不含 `collapsed`**、箭头仍 `▾`。
- 断言其它未展开书卡不受影响(仍 `collapsed`)。

# #2(P1) 专注模式重做: 单卡 + 原文语境入卡 + 背景模糊 + 语音按钮

**用户诉求**: 点「开始复习」后队列不再单独显示(前面已看过今日队列); 一张独立卡片,
原文语境放卡片里; 卡片底下内容模糊掉/悬浮; **必须有语音按钮**, 正常速度 / 慢速两档; 桌面手机都要。

**方案(已确认: 桌面高质量, 手机系统级, 都必有语音)**:
- **review_view 重做**: 去三栏 grid, 改单卡:
  - 正面: 词 + 音标 + 原文语境(原右栏内容并入卡内)。
  - 背面: 释义 + 来源定位。
  - 背景: 遮罩 + 卡片悬浮(`backdrop-filter` 模糊, 复用 tokens 的纸面变量, 不裸 hex)。
  - 退出/Esc 保留, 进度保留。
- **语音(两个按钮: 正常速度 / 慢速)**:
  - **桌面**: 词条带 `edition_id+chapter_index+sentence_index` → 走阅读器音频管线
    (`loadBookpackChapter` + `read_audio`)播原句; 慢速 = `audio.playbackRate = 0.75`;
    无音频/加载失败 → fallback speechSynthesis。
  - **手机**: `speechSynthesis.speak`(rate 1.0 / 0.6)读单词(系统级)。
  - 播放中按钮有状态(如 `playing` 类高亮)。

**验收(教训 8)**: 点开始复习 → `.review-grid` 消失、单卡出现且卡内含原文语境块; 两个语音按钮
文案「正常速度」/「慢速」; 点击后播放状态类变化; 背景遮罩/模糊层存在。

# #3(P1) M3 落地: 同步和数据 → 账户主体 × 后端勾选

用户: 「同步和数据这里没有账户主体和需要同步哪些后端的选择指定」。**之前为什么没做**:
UX4 GOAL 明确把 M3 移出(当时 M0 手机端从未成功同步 + 存储层风险)。现在 M0 已验证, 用户要求,
**按已定稿设计结论执行, 不再重新讨论**:

- 概念(界面上说人话): **主体/用户**(顶栏"我")× **后端**(词库同步到哪台服务器)×
  **token**(某主体在某后端的凭据, 交叉物)。
- 矩阵: 每个 (主体, 后端) 一格 = token + 是否启用同步; 一个主体可同时启用多个后端;
  同步 = 对当前主体已启用后端依次先推后拉; 冲突 `updated_at` 新者胜。
- 设置页: 后端列表每项加**「同步此后端」勾选** + 显示所属主体; 切主体后看到该主体自己的启用状态。

**存储改动(本卡主体, 单独提交, 迁移兜底)**:
- `sync_state` 主键 user_id → 复合主键 (user_id, endpoint_key); 老行按当前 endpoint_key 落一行。
- credentials token key 从 user_id → user_id+endpoint; 迁移: 老 key 读得到就迁, 迁不动明确报错。

**验收**: 同主体启用两个后端 → 一次「立即同步」两边都收到(各自推 N 条); 取消其一 → 只推另一个;
切主体后看到该主体自己的后端启用状态。

# #4(P1) 书库位置 = 数据根(子文件夹 + 绿色生效徽章 + 首次默认)

用户: 「数据目录和数据库应该都跟随在书库位置的下面的子文件夹。应该是绿色的。不要什么都放到
C 盘 data 里面。用户不可见。是不对的」。

**布局(我决定)**:

```
书库位置/                 (用户选定, 可见; 生效时绿色徽章)
├── data.db
├── config.toml
├── jobs_out/            (成品, 现有语义不变)
├── models/              (模型下载默认目录)
├── backups/             (迁移/操作备份)
└── logs/
```

- **更改… = 整根迁移到新位置**(config + db + out 一起), **走 L1 清单校验 + 先备份 +
  校验通过才删旧**, 完成后重启。原位置文件一个没少。
- **绿色生效徽章**: 当前生效位置存在且可写 → 绿色; 失效/不可写 → 红/灰 + 原因。
- 「加载已有书库…」语义不变(扫描登记), 意义变为"往这个数据根里并入旧成品"。
- **首次默认(我决定)**: 向导第 2 步默认推荐 **`我的文档/aidulc`**(Windows `%USERPROFILE%\Documents\aidulc`,
  含 OneDrive Documents), 可见、可预期、符合用户心理学; 该步显示完整结构引导
  (data.db/jobs_out/models/logs 各一行说明), 用户可改。
- 现有 `dataMigrationStatus`(程序目录→数据目录)折叠进这套: 检测到旧位置有数据 → 引导
  "一键把旧数据迁到新的书库位置"。

**验收**: 更改到新位置后 data.db/config.toml/jobs_out/ 都在新位置子项下, 徽章绿色; 原位置
文件一个没少(前后计数); 重启从新位置读; 向导默认位置可见且结构说明清晰。

# #5(P1) 模型与依赖: 逻辑闭环(选目录→搜索→版本/更新)+ 去无意义项

用户逻辑: 「我选择目录。然后可以搜索现有模型。如果没有。推荐, 我可以点下载, 如果有。
我可以看到是否最新版本。是否需要更新下载。」

- **模型目录显示**: 模型页顶部显示模型目录(已登记 llm/tts 路径目录 + HF 缓存, 复用 M4 扫描路径), 可增删。
- **nlp 段**: 无已登记 nlp 模型时**整段隐藏**(不是用户要配置的东西); 有才显示。
- **版本/更新判定(新能力)**: 扫描候选带 `family_hint + size_bytes`; "是否最新/需更新" =
  候选 vs 下载目录(DOWNLOAD_CATALOG)已知版本比对:
  - 无已登记 → 「可下载/可登记」。
  - 已登记且文件在 → 版本 + 「已是最新」或「有新版 vX, 可更新」。
  - 版本未知 → 老实显示「版本未知, 无法判断」。

**验收**: 选目录→扫描→无候选给下载推荐; 有候选显示路径/大小/版本状态/是否需更新;
nlp 段无 nlp 模型时不渲染; 模型目录路径在页面上可见。
