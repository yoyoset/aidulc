# 便利性/完整度需求挖掘(2026-08-15)

## 这份文档是什么

跟 2026-08-14 的"成熟度审计"(见 `ROADMAP.md`"成熟度审计"节)是两种不同性质的挖掘:

- 2026-08-14 那轮找的是**正确性/边界缺口**——按 CLAUDE.md 的五个维度(配置管理/
  外部系统集成/依赖交付/状态管理/错误反馈)逐域核对, 找"会出错但没处理"的地方。
- 这一轮找的是**便利性/完整度缺口**——不是"错了", 是"一个成熟产品这里通常会有,
  但这里没有"。起因: 用户实测书库页发现排序/卡片大小/生词发音都是这类"顺手的
  需求", 用户原话"这种需求我还是觉得应该是成熟度带出来的, 而不是我需要想到的"。

用 progate(deepseek-v4-pro)逐域深挖, 编排方(当前会话)只做范围框定和轻量复核,
**这一轮不改代码**, 只产出带方案选项和取舍权重的报告, 由用户最后拍板选哪些做。


### 书库/封面 搜索只匹配书名、不匹配作者

**对比**: 微信读书/Kindle/Calibre 都支持按作者搜到该作者全部书; "记得是村上春树那本、想不起书名"是极常见场景。
**方案选项**:

**建议权重**: 高(方案 A)—— 高频 + 改动极小。

**建议权重**: 中高(方案 A)—— 高频且是"成熟度"硬指标, 但需后端支持批量删除(目前 `remove` 是单 id, library_service.js 第 23 行)。

**对比**: 词典类产品(欧路/必应/微信读书查词)都有"最近查询"或"历史"列表, 这是查词最顺手的回看通道。
**方案选项**:
  - 方案 A(会话内最近查询列表, 前端内存): `DictionaryPanel` 存一个 `Map<word, 最近一次结果>`, 面板顶部加"最近"折叠区, 点击直接重渲染缓存结果。零后端, ~20 行。缺点是重启丢失。
  - 方案 B(后端落库历史): 加 history 表/字段 + 命令, 跨会话。改动大, 收益相对低。
**建议权重**: 中(方案 A)—— 高频且零后端, 但只存内存是明确取舍。

### 阅读器 摘录无搜索/标签, 书签无导出

**现状**: 摘录面板 `highlights.js::togglePanel`(第 142-225 行)只是按章/句序全量列表, 没有搜索框、没有标签/颜色分类;
备注是内联 textarea(第 254-283 行), 无富文本/加粗等。全书摘录有 Markdown 导出(`_exportMarkdown` 第 229-251 行),
但**书签没有导出**(`bookmarks.js` 只有面板展示, 无导出入口)。攒了上百条摘录后, 找一条只能靠滚动翻。
**对比**: 笔记类产品的笔记通常支持搜索/标签/筛选; 书签(尤其带句文本的)同样应该能导出成一份"金句清单"。
**方案选项**:
  - 方案 A(摘录面板加搜索框): 复用 SearchIndex 或纯子串过滤, ~15 行。
  - 方案 B(书签导出 Markdown): 仿 `_exportMarkdown`, 把全书书签(带章/句文本)导成一份文件, ~25 行。
  - 方案 C(标签/颜色分类): 需后端加字段, 改动大, 记 ROADMAP。
**建议权重**: 中(A、B 均中)—— 都是"导出/查找产出物"这一类的补齐, 单看都不大。

### 阅读器 没有全书级阅读进度可视化

**现状**: 顶栏只有"今日 X 分钟"(`reader_view.js` 第 374-376 行, 且 `_loadTodayStats` 第 274-281 行只在打开时拉一次, 不实时走字);
周统计面板(`_showReadingStats` 第 679-728 行)只有按天时长条形图; 底部 3px 进度轨(`player.js` 第 56-66 行)是**当前章音频**的播放进度, 不是阅读进度。
整本书读到哪了、还剩多少, 没有任何一处可视。章节尺只有"当前章高亮", 没有"已读/未读"着色。
**对比**: 成熟阅读器在书库/阅读器内都会给"本书已读 X%", 章节列表标已读/未读; 读整本书一年的用户很关心"还差多少读完"。
**方案选项**:
  - 方案 A(章节尺标已读 + 顶栏加全书进度): 用 `verified` 数据把已核对过的章标色 + 顶栏加全书进度百分比(按章数或句数)。改动 ~20 行。
  - 方案 B(独立阅读进度页): 每章核对进度 + 时长热力图。改动大。
**建议权重**: 中(方案 A)—— 观感收益大, 改动小, 但依赖"已核对"口径的定义需拍板。
