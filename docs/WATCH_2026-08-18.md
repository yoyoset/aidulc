## 新发现 2(真 BUG): `nlp_realign` 被算进"失败句数", 用户看到的失败数被放大几十倍

| Frindle | 1245 | 1209 | 36 |

| Tuck Everlasting | 154 | 0 | 154 |
| Charlottes Web | 35 | 0 | 35 |

传播路径(全部读的是 `failedSentences.length`, 没有按 stage 过滤):
- [`reader/views/prep_view.js:438`](../reader/views/prep_view.js) → 任务详情弹窗的「失败句数」

(a) `nlp_realign` 不进 `failedSentences`, 单开一个 `realigned` 计数;
(b) 保留在列表里但所有消费方按 stage 过滤掉它。
倾向 (a) —— 语义上它就不是失败, 留在失败列表里迟早还会被下一个消费方读错。

### 更正: 我预测 0.6~0.7%, 实测 12.49% —— 预测错了

心跳任务里我写的预期是"这本书用 8/18 最新提示词, 废话率应该在 0.6~0.7% 量级
(对照 Charlottes Web 0.7% / Despereaux 0.6%)"。**实测 12.49%**, 落在**未重做的
那 8 本**(7.8~14.5%)的区间里, 不是重做过的两本那一档。

预测错在哪: 我把"六类清单进了提示词"直接等同于"所有新跑的书都会拿到低废话率",
没有检查**提示词是不是被完整拼出来**。查 `explain_system_for` 的实现:

```python
base = EXPLAIN_DEEP if strategy == "deep" else EXPLAIN_BRIEF
if max_chars:                      # ← 这个 if
    base = f"{base}\n讲解长度按句子难度自适应: 简单句一两点讲完即可(30-60 字); …"
```

**`max_chars` 为假时, 整段长度指令(含"简单句一两点讲完即可")根本不拼进去。**
而 The Giver 的 `job_request.json` 里 profile 只有三个键:

```json
{"explain_strategy": "brief", "id": "default", "name": "成人自读"}
```

—— **没有 `explain_max_chars`, 也没有 `explain_min_sentence_chars`**。

### 根因(代码级已确认): 新书路径把 K33 两个字段整个丢了

`reader/services/import_service.js::getProfile` 从档案表取到 profile 后, 是用**显式
白名单**重新拼一个对象的:

```js
return {
  id, name, explain_strategy, voice, speed, highlight_granularity,
};   // ← explain_max_chars / explain_min_sentence_chars 不在列表里
```

于是用户在设置里配的"讲解字数上限 / 触发门槛"在**新导入的书和"开始阅读准备"这条
路径上被静默丢弃**, Rust 侧按缺省填 150/0。用户这次设的是 default 档案 max=50 /
min=80, 一个都没进去。

**这和 8/16 修过的那个 bug 是同一类, 同一个错法, 只是换了个地方。**
`job_orchestrator.rs::profile_from_snapshot` 的注释里白纸黑字写着:

> K33 的 explain_max_chars/explain_min_sentence_chars 原本不在拷贝列表里,
> 重跑会静默丢掉用户设的讲解字数上限/触发门槛, 退回默认值。

当时只修了**重跑**那条白名单, 没有回头查还有没有别的地方在做同样的字段拷贝。
现在数一下, 这两个字段一共有四条组装路径:

| 路径 | 带不带 K33 两字段 |
|---|---|
| 重跑时重选档案 (`picked_profile`, Rust 读 profiles 表) | ✅ 带 |
| 重跑时保持原档案 (`profile_from_snapshot`) | ✅ 带(8/16 修的) |
| **新书导入 / 开始阅读准备 (`import_service.js::getProfile`)** | ❌ **丢** |
| 内建兜底 (`core/builtin_profiles.js`) | ✅ 带(硬编码 150/0) |

8/18 早些时候用户问"我设的字数门槛没起作用是吗", 我答的是"重跑复用旧快照, 要在
