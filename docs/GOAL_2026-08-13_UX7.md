## 一、用户反馈(原话整理)

1. **打开书籍或点击章节 → 弹出「音频加载失败」**; 然后**选取单词加入生词本也失败**。
2. **需要浮动按钮全局停止**: 自动开始读以后, 点句子前的按钮重新读, 再点一下才能停。
   现在没有一个"全局停止"的出口(只能等句末/章末或逐句暂停)。
3. **书签功能没了, 要找回**: 需要能记录书签并持久化。
4. **选中句子有"摘要"功能, 添加了摘要怎么调出?** 实际就是在问**摘要/笔记的入口**在哪。

## 二、现状核实(已读代码确认, 不是猜测)

### #1 音频加载失败 + 加词失败

- 音频链: `reader_view.open()` → `_loadChapter()` → `player.loadChapter(ch)`
  (`reader/views/reader/player.js:72`) → 分块 `readAudioRange(basePath, ch.audioFile, ...)`
  → `src-tauri/src/commands/library.rs:926` 读 opus 文件返回 base64。
  - **已接线**: `ipc/registry.rs:77` 有 `read_audio_range`, 不是"未接线死代码"。
  - 失败面: `player.js:111` 抛「音频加载失败: <e.message>」。
- 加词链: `_onWordClick` → 词典面板 → `addToVocab` → `add_vocab`(reader.rs:207)。
- **待实测定位**(不猜): 是 `basePath`/`audioFile` 路径不对、书包音频文件缺失、
  还是新构建引入了回归。用户描述"打开书或切章"都失败 → 更像**路径/文件**问题而非单句问题。
  (UX5 曾修过"迁移后 books.pack_dir 被删导致红卡", 需确认用户当前书的 pack_dir/音频文件是否在。)
- **2026-08-13 用户补充实测细节(推翻上面"路径/文件缺失"这个主假设)**: 音频**实际播放正常**,
  但仍会弹出一条「音频加载失败」toast, **一闪而过**, 用户没看清、也不知道从哪触发的。
  这说明不是文件真的缺失/路径真的错(否则播放不会成功), 更像是**某条异步请求失败但被后续
  成功的请求盖过/掩盖**——即误报, 不是真失败。**新的主假设**: `player.js` 的 `_generation`
  代际计数 + `cleanup()`(player.js:303 起)是为处理"切章/重开时取消上一次未完成加载"设计的,
  ROADMAP 里"打开书并行化(4 个 IPC 改 `Promise.all`)"(M7 Round 19-21)之后, 大概率是**旧一代
  的 `readAudioRange` 请求在新一代加载已经成功之后才 reject/超时**, 它的 `.catch` 依然跑
  了 `player.js:111` 那行 `_onStatus('音频加载失败: ...')`, 但此时页面已经在播新音频了,
  所以观感是"音频正常但报错一闪"。**待实测定位**: 复现时除了看 `aidulc.log`, 重点看
  `readAudioRange` 的 reject 是不是来自一个**已经被取消的旧 generation**, `.catch` 里
  有没有按 generation 判断"这条失败是不是还有效"就直接扔了 toast。

### #2 全局停止按钮

- 现状: 句前 `atool-play`(▶/❙❙) 可**单句**暂停/播放(atomic_block.js:285-296);
  空格键 `_onSpace` 是播放/暂停;**没有任何"全局停止并回到当前句起点"的浮动出口**。
- 用户诉求原文是"自动开始读以后, 点句前按钮重新读, 再点一下才能停" → 想要:
  一个**可见的浮动停止按钮**(不依赖键盘), 点了立即停, 再点重读。
- **复核确认已有可直接复用的语义**: `player.js:294` 的 `toggle()` 注释原文就是
  "全局播放键: 点一下开始(从锚点句), 再点一下停止", 且 `playFrom()`(player.js:172)
  每次都把 `audio.currentTime` 重置到句首, 所以"停止后再点 = 从当前句重读"这个语义
  `toggle()` 已经完整具备。`reader_view.js:1053-1057` 的 `_onSpace()` 在"通篇"节奏下
  已经在调 `this.player.toggle()`。**结论**: 不需要新写停止/重读的状态编排逻辑, 缺的
  只是一个绑定到 `toggle()` 的**可见按钮**。

### #3 书签找回

- 现状: `reader/views/reader/bookmarks.js` 完整存在(Set<句下标> + 面板 + 落盘回调)。
- **入口藏在 Ctrl+K 命令面板**(command_palette.js:44「📋 书签面板」), 顶栏没有直接入口
  —— 用户没找到 = "书签没了"的真相之一。
- **真正丢书签的 bug(R4-1 相关)**: `_restoreState`/`_loadChapter` 里切章时
  `bookmarks.restore([])` 清空内存集合;**落盘却只存"当前章"的一组句下标**
  (`_saveProgress` 写 `bookmarks: Array.from(this.bookmarks.bookmarks)`)。
  → 书签只在"当前章会话"里活着, 切章即丢, 重开只剩最后一章的, 且没有"整本书书签列表"。
  **需要实测确认**: 书签语义应该是"每章一组"还是"整本共享"——目前看是按"当前章句下标"
  存的, 跨章互覆。要找回 = 改成**按章存**或至少**整本书书签列表可遍历**。
- **`bookmarks.restore([])` 实测枚举, 不止两处**: `reader_view.js` 里这行调用一共
  **4 处**——61(打开书初始化)、582(`_loadChapter` 切章)、591(R4-1 已修的搜索跨章跳转)、
  659(另一条恢复路径)。改后端存储格式时这 4 处都要跟着改成"读该章书签", 漏一处就会
  在对应场景下继续复现"书签没了"。
- **后端已有一个接线了但前端零调用的命令**: `commands::reader::bookmarks_list`
  (`src-tauri/src/commands/reader.rs:1290`, 在 `main.rs:519`/`ipc/registry.rs:273`
  都已注册, 返回 `state.bookmarks`)——全仓库 grep 前端代码找不到任何调用点。它现在
  拿到的是本节要改的旧格式(整本一组下标), 格式定下来之后要么把它接成"整本书书签遍历"
  的数据源(对应第五节验收"重开书 → 各章书签可遍历"), 要么明确决定不用它、删掉这处死代码
  ——不能像现在这样留着不接。

### #4 摘要/笔记入口

- 现状: 摘录标注(highlights)完整存在: 选中文字 → 浮动"摘录"按钮 → 保存(highlights.js);
  面板 `togglePanel()` 也**藏在 Ctrl+K 命令面板**(command_palette.js:48「📕 摘录」)。
- 用户理解正确:"选中句子有摘要功能, 添加了怎么调出" = **摘要笔记的入口在 Ctrl+K 命令面板**,
  但同样没有显眼入口。
- 本轮要做的: ①确认"选中文字→摘录"链路可用; ②给书签/摘录一个**显眼的入口**
  (顶栏按钮或正文内直接按钮), 不是只藏在 Ctrl+K 里。

## 三、方案(定稿, 按序执行)

顺序: **#1(实测定位修复) → #2(全局停止) → #3(书签找回) → #4(摘要入口)**。一条一提交。

### #1(P0) 音频加载失败 + 加词失败 —— 先实测定位

1. **实测定位**: 打开用户的真实书包, 复现「音频加载失败」, 看 `aidulc.log` 里
   `readAudioRange` 的具体 error(文件不存在/路径越界/base64 空/字节率)。
   同时复现加词失败, 看 `add_vocab` 返回什么(是词典守护失败连带的, 还是 profile/user 问题)。
2. **修**: 按实测根因修(音频文件缺失 → 提示"这本书没有音频, 只读文本";
   路径问题 → 修正 basePath; 加词失败 → 修对应链路)。
   保持: 失败可读 + 可重试, 绝不静默。**加词失败若与词典守护有关, 确认 UX6 #2 修复后已自愈。**

### #2(P1) 浮动全局停止按钮

- 新增一个**常驻浮动按钮**(仅播放中显示, 或始终显示但禁用态): 右下角圆形按钮
  `⏹ 停止` / `▶ 播放`(随 `player.playing` 切文案图标)。点击 → 直接调
  **`player.toggle()`**——不重新编排 stop/playFrom, `toggle()` 已经是"停了再点从当前句
  重读"的完整语义(见二、#2 复核), 这样也和空格键 `_onSpace()` 走同一条状态机, 不会分叉
  出第二套行为。
- 与句前 ▶/❙❙ 的关系: 句前按钮仍是"这句"语义; 浮动按钮是"全局停/重读", 调用面不同但
  底层状态(`playing`/`anchorIndex`)共享, 不会互相打架。
- **零 DOM 纯逻辑放哪**: 按钮是纯 DOM 组件, 放 `reader/views/reader/global_stop.js`
  (仿 follow_bar/silent_card 模式), 只订阅 `player.playing` 状态, 点击调
  `player.toggle()`, 本身不持有播放逻辑。
- smoke: 断 DOM——播放中出现「停止」按钮、点击 → `player.toggle()` 被调 + 文案切换、
  再点 → 再次调 `toggle()` 且从当前句重读(`playFrom` 被间接触发)。

### #3(P1) 书签找回(按章持久化 + 显眼入口)

1. **持久化语义修正**: 目前 `_saveProgress` 只存当前章一组下标。改成**每章一组**:
   `reading_state.bookmarks` 从 `number[]` → `{ [chapterIndex]: number[] }`。
   **迁移方式定死为版本化迁移, 不做应用层猜格式转换**: `bookmarks` 列本身是 TEXT/JSON,
   不需要 `ALTER TABLE`, 但结构变化仍按仓库现有惯例走一个编号迁移(`data_migration.rs`
   里 v20/v24 那种模式)——当前最新是 **v25**(`model_registry.detected_family`),这次是
   **v26**: 逐行读旧 `bookmarks` JSON, 是数组就套成 `{ [该行 chapter]: 数组 }`, 是对象就
   保持不变(幂等, 防止迁移重跑)。配一个 Rust 迁移测试(老库 v25 状态 → 升到 v26, 断言
   数组按 `chapter` 归位)。理由: 和其余所有结构性变化保持同一套可审计的迁移记录, 不额外
   引入"读时候猜格式"这种隐式分支。
   前端 4 处 `bookmarks.restore([])`(reader_view.js:61/582/591/659, 见二、#3 实测枚举)
   全部改成"读回当前章那一组", 不再传空数组清空。
2. **入口**: 顶栏加「🔖 书签」按钮(点击 showPanel)或正文句前加书签按钮,
   不再只靠 Ctrl+K。Ctrl+K 里的入口保留。
3. **`bookmarks_list` 命令(reader.rs:1290)接上**: 格式改完后, 用它给"全书书签遍历"
   提供数据源——书签面板(`bookmarks.js` 的 `showPanel`)在打开时除了当前章的内存 Set,
   额外拉一次 `bookmarks_list` 展示全书各章书签, 点击可跨章跳转。这样第五节验收
   "重开书 → 各章书签可遍历"才有真正落地的 UI, 不是只改数据格式没有入口。
4. 后端: v26 迁移 + Rust 单测(老数组 → 新按章结构, 幂等)。
5. smoke: 加书签 → 切章 → 回该章书签还在; 重开书 → 书签面板列出各章书签且可点击跳转。

### #4(P1) 摘要/笔记入口 + 确认链路

1. **确认**"选中文字 → 摘录"整条链路在真实 exe 可用(可能被 #1 音频失败连累, 先修 #1)。
2. **入口**: 顶栏加「📕 笔记」按钮(点击 togglePanel), 或与书签一起做成顶栏两个小按钮。
   Ctrl+K 入口保留。面板内空态文案讲清楚: "阅读时选中一段文字, 点『摘录』保存; 这里列出全部笔记"。
3. smoke: 顶栏出现「📕 笔记」按钮 → 点击调出面板; 面板有摘录行可点回跳。
