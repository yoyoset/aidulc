## 设计稿与现实的六处冲突(先解决再画)

1. **§03"词条不上传"与手机端矛盾**:Web 端没书包没词典模型,不传卡就是空的。
   改为同步词条最小集(词/音标/释义/来源句,约 300-600B/条,5000 词≈2MB),不传书正文。§03 该句作废。
2. **1 分钟/10 分钟存不下**:`interval_days` 是 INTEGER 天且按 `as i64` 截断 → 分钟级变 0。加毫秒级字段,
   `interval_days` 只留作 AIDU 导出兼容。
3. **按钮上的四个时间不许前端写死**:必须由调度器对当前词算出后返回,否则算法一改按钮不跟着变。
4. **user ≠ profile**:现状拿 profile(讲解策略)当人用。引入独立 `user` 维度,profile 退回策略语义。
   迁移映射:每个现有 profile → 一个 user(default→我、kid→孩子),事务内完成、可回滚。
5. **user 必须由服务端从 token 解析**,客户端不许自报。Web 端公网可达,自报 user = 谁都能读别人的词库。
   接口带 `/v1/` 前缀,user_id 由服务端签发且稳定(将来加账号只换发 token,不动数据)。
6. **手机端"跳到原文"做不到**(无书包):改不可用态提示"在电脑上打开",桌面端保留跳转。

## 全局同步规则(两端一致)

- **先推后拉**:每次同步先推本地未推的改动,再拉远端;**任何情况下不许先拉覆盖未推的本地改动**。
- 冲突按 `updated_at` 新者胜(复用 `domain/sync.rs`)。KV 是镜像不是真相源。
- **写配额是硬约束**:同步必须做到**一次会话 O(1) 次写**(整批提交),不能一张卡一次写。
  免费路径是**用户拿自己的 CF 额度自建**,写得越省用户越不会撞上限;V0.2 先测实际额度再定阈值。
- 两端都要离线可用:离线照常复习,恢复网络自动补推,不丢数据。
- **服务端只存 SRS 状态 + 词条最小集(含来源单句),绝不接收、不存储书文件或整章正文。**
  这是硬边界:书的获取与处理全程留在用户自己机器上,服务端不进入这条链路。

## 三项已定(照做,不要再问)

**① 邀请与加入**:**worker 实例 = 一个家的空间**,不另造 family_id。部署时设 `ROOT_SECRET`;
首台桌面端用 URL+ROOT_SECRET 换到第一个 user("我")与设备 token,此后不再需要它。
已登录设备可生成 **6 位数字码**,两种类型:`add-device`(绑现有 user)/`invite-user`(服务端新建 user,对方填名字)。
码 10 分钟有效、一次性;**必须配错码限速**(如 5 次错误锁 15 分钟),否则 6 位数字就是个洞。
**一台设备可持有多个 token**(顶栏切人 = 切 token)——电脑/pad 会共用,设备不属于某个人。
设置里列出设备并可踢掉(删 KV 里的 token),丢手机时用。付费托管走同一套:作者签发 ROOT_SECRET 即开通。

**② 每日配比(给规则不给数字)**:到期复习**不封顶**(债不能拖);新词**有上限且随负债收缩**:
`新词额度 = clamp(基础值 - max(0, 到期数 - 舒适线)/2, 0, 基础值)`,基础值默认 6(设置可调 0-20,kid 默认 3),
舒适线默认 20。**"学习中"(分钟级步长未毕业的卡)不占配额**,到点即插队 —— 设计稿把它单列成 5 是展示口径,
不是第三个配额。顺序:到期复习 → 学习中插队 → 新词;这样中途退出损失的是新词(明天可补),
不是到期复习(拖了会忘)。"预计用时"按**实测每卡中位耗时自适应**,无数据时按 15 秒/张,不写死。

**③ 迁移不拆人**:V1 把**全部现有数据归到一个 user("我")**,profile 保持讲解策略语义(default/kid 都留着)。
**不许猜 kid profile 的词属于孩子** —— 迁移自动且不可逆,猜错要重做;建成员是用户主动且可逆。
改为在 UI 提供"新建成员 + 把词搬过去"(V4 有来源定位后可按书批量选)。
副作用是好的:V1 迁移简化成所有行填同一个 user_id,风险和测试都小一截。
